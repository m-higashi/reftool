# 文献リファレンスツール

このフォルダ(`教科書/`)以下の PDF / PPT / PPTX を管理・検索するローカル常駐型 Web アプリです。
文献ファイル本体には一切手を加えません(移動・リネーム・削除・上書きをしない)。

---

## 0. 入手方法(GitHub から)

**かんたんな方法** — ソフトの追加は不要です。

1. GitHub のページを開き、ファイル一覧の**右上にある緑色の「Code」ボタン**を押します
2. メニューのいちばん下の **「Download ZIP」** を押します
3. ダウンロードした ZIP を展開します
4. できたフォルダの名前を **`_reftool`** に変更します
   (展開直後は `reftool-main` のような名前です。**この名前でないとアプリが読み取り対象を
   判定できません**。先頭のアンダースコアも必要です)
5. 管理したい PDF が入っているフォルダの直下に置きます

**git を使う方法** — 更新を受け取りやすくなります。末尾の `_reftool` を忘れないでください。

```bash
git clone <リポジトリのURL> _reftool
```

更新するときは `_reftool` の中で `git pull` するだけです。作成されるデータ
(`library.db` / `backups/` / `.venv`)は更新の対象外なので消えません。

ZIP で入れたものを新しい版に差し替えるときは、中身だけを上書きします(データは残ります)。

```bash
rsync -a 展開したフォルダ/ 置いた場所/_reftool/
```

## 1. 起動方法(Windows)

1. `_reftool\start.bat` をダブルクリックします。
   - **初回のみ**、仮想環境の作成と依存パッケージのインストールが自動で走ります(数分)。
     必要なのは Python 3.11 以上(推奨 3.12+)がインストール済みであることだけです。
2. コンソールウィンドウに **アクセス用 URL** が表示されます。ブラウザで開いてください。
   ```
   このPCから   : http://127.0.0.1:8585/
   LAN/Tailscale: http://100.x.x.x:8585/
   ```
3. 停止するには、コンソールウィンドウを閉じるか `Ctrl+C` を押します。

> コンソールはログ表示のため出したままで構いません。

## 2. 設定(`_reftool\config.toml`)

テキストエディタで編集し、ツールを再起動すると反映されます。主な項目:

| 項目 | 説明 |
|---|---|
| `[server] host` | バインドするIP。同一PCのみなら `127.0.0.1`。**Tailscale越しに使うときはそのPCのTailscale IPを書くか、`0.0.0.0` のまま**にする |
| `[server] port` | ポート番号(既定 8585) |
| `[labels]` | メモ欄2つのラベル名(既定「メモ」「目次」) |
| `[categories]` | カテゴリ一覧と、**フォルダ名→カテゴリの自動判定ルール**。`keyword` がパスに含まれれば `category` を割り当てる |
| `[crossref]` | DOIからの補完のON/OFF・連絡先メール |
| `[backup]` | 自動バックアップの世代数(既定30) |

### カテゴリの自動判定
- 各ファイルは、所属フォルダのパスに設定ルールの `keyword` が含まれるかで初期カテゴリが決まります。
  既定では `雑誌`→雑誌、`論文`→論文、`教科書`→教科書、`ネット`/`web`→ネット、どれにも該当しなければ「それ以外」。
- **UIで手動変更したカテゴリは、再スキャンで上書きされません。** 手動値を空に戻すと再び自動判定に従います。

## 3. 使い方

- **上部バー**: 検索ボックス / カテゴリ・状態・フォルダ・既読フィルタ / ★のみ / 並び替え / 各種ボタン。
- **再スキャン**: フォルダを再走査して追加・欠落・移動を検出します。スキャン完了後、新規・変更ファイルのメタデータ抽出が自動で走ります。
- **メタ抽出**: 未抽出ファイルのタイトル・DOI等を抽出します(通常は再スキャン後に自動実行)。
- **一覧の行をクリック**すると右側(スマホでは下)に詳細パネルが開き、
  - タイトル・雑誌名・DOI・カテゴリ・メモ2つを編集・保存(自動保存)
  - PDFはブラウザ内表示、ppt/pptx はダウンロード
  - ファイルパスのコピー、BibTeX / プレーン引用のコピー
  - Crossref 補完、移動候補への再紐付け、重複の確認
  ができます。
- **★(お気に入り)** と **読書ステータス(未読/読書中/読了)** は一覧・詳細から設定でき、フィルタで絞り込めます。
- **NEW バッジ**: 前回スキャン以降に追加されたファイル。確認したら「NEW全解除」または各文献で個別解除できます。
- **要対応バッジ**: ファイルが見つからない(移動/リネーム/削除)か読み込めない場合に付きます。移動の場合は同一内容のファイルが提示され、ワンクリックで再紐付けできます。

### 検索
- 対象: 正式文献名 + 雑誌名 + メモ1/メモ2 + ファイル名。日本語対応(SQLite FTS5 trigram)。
- 2文字以下の短い語は部分一致(LIKE)で検索します。

## 4. 別のPCへの移行(可搬性)

DB内のファイルパスはこのフォルダからの**相対パス**で保存され、設定に絶対パスは含みません。

1. `教科書` フォルダごと新しいPCにコピーする(`_reftool` も含む。`.venv` はコピー不要で、初回起動時に再生成されます)。
2. `_reftool\config.toml` の `[server] host` を、**新しいPCのTailscale IP**(または `0.0.0.0`)に書き換える。
3. `_reftool\start.bat` をダブルクリックする(初回は依存の再インストールが走ります)。

> `library.db` をそのまま持っていけば、編集したタイトル・メモ・カテゴリ・お気に入り等も引き継がれます。

## 5. Windows ファイアウォール

Tailscale や LAN 越しにアクセスするには、受信接続の許可が必要な場合があります。

- 初回起動時に「Windows セキュリティの警告」が出たら、**プライベートネットワーク**にチェックして「アクセスを許可」。
  **「キャンセル」を押すと python.exe のブロックルールが自動作成され、以後 Tailscale からも繋がらなくなる**ので注意。
- 手動で追加する場合(管理者権限のPowerShell):
  ```powershell
  New-NetFirewallRule -DisplayName "reftool 8585" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8585
  ```

### Tailscale から繋がらない時のチェック
1. ブロックルールの有無を確認: `netsh advfirewall firewall show rule name=python.exe dir=in verbose`
   - `操作: ブロック` の規則があれば、それが原因(過去に警告ダイアログでキャンセルした痕跡)。
2. 対処はどちらか:
   - 管理者権限でブロックルールを削除する: `netsh advfirewall firewall delete rule name="python.exe" dir=in`
   - **ブロック対象と別パスの python で起動する**(start.bat はこの方式を自動採用):
     ブロックは exe のフルパス単位で効くため、`%LOCALAPPDATA%\Python\bin\python.exe`(エイリアス)から
     起動すればルールに一致せず、Tailscale の受信は通る。依存は venv を `PYTHONPATH` で参照する。

## 6. セキュリティ

- 認証はありません。**Tailscale 内(または信頼できるLAN内)でのみ公開してください。**
- **インターネット(Tailscale外)には絶対に公開しないこと。** `0.0.0.0` バインドのまま公開ポートに晒すと誰でもアクセスできます。

---

## 7. バックアップ

- 起動時に1日1回、`_reftool\backups\` にDBを日付付きでコピーします(既定30世代保持、古いものは自動削除)。
- UIの「バックアップ」ボタンで、いつでも手動バックアップ(時刻付きファイル)を作成できます。

---

## 8. 他端末同期(2台運用)

メイン端末で整理した内容(ファイル配置+メタ情報)をサブ端末へ反映する機能です。

1. メイン端末で「バックアップ」→ `backups/` の最新 `library-….db` と新規文献ファイルをサブ端末へコピー
   (ファイルの置き場所は`教科書`フォルダ内なら任意。内容ハッシュ sha1 で照合するため)。
2. サブ端末のUIで「他端末同期」→ バックアップを選択 → **プレビュー**で計画を確認 → **同期を実行**。

実行時の動作: ①現DBを退避バックアップ → ②バックアップDBの `files` を取り込み(FTS再構築) →
③ファイルを記録どおりの場所へ2相移動(ステージ経由。入替・玉突き対応、失敗時は元へ戻す) →
④空フォルダ削除 → ⑤再スキャン+メタ抽出。

- プレビューの区分: 配置一致 / 移動予定 / 不足(サブ端末に実体なし→欠落登録) /
  この端末のみ(記録外→そのまま残しNEW登録) / 競合(移動先に記録外ファイル→スキップして報告)。
- ファイルの中身は書き換えません(移動のみ)。API: `/api/sync/backups|preview|apply|status`。
  実装は `reftool/sync.py`。`/#sync` で同期画面を直接開けます。
- 利用者向け手順は `使い方・運用ガイド.txt`「■ 2台のPCで使う(他端末同期)」参照。

## 9. 構成・技術

- Python + FastAPI + Uvicorn + SQLite(FTS5 trigram)+ 素の HTML/JS。
- 主要ファイル:
  ```
  _reftool/
    config.toml        設定
    run.py             起動エントリ
    start.bat          Windows起動スクリプト
    requirements.txt   依存
    library.db         DB(自動生成)
    backups/           自動/手動バックアップ
    reftool/           サーバ本体(config/db/scanner/metadata/cite/backup/sync/server)
    static/            フロントエンド(index.html/app.js/style.css)
  ```

### DBスキーマのマイグレーション方針
- `meta` テーブルの `schema_version` で現在のバージョンを管理します。
- スキーマ変更時は `reftool/db.py` の `MIGRATIONS` に `(旧バージョン, 適用SQL)` を追記し、`SCHEMA_VERSION` を上げます。
  起動時に不足分の `ALTER/CREATE` が順に適用されます。破壊的変更の前には起動時バックアップが効きます。

## 10. 目次の一括登録(後続タスク)

全PDFの目次を抽出してメモ2(既定ラベル「目次」)へ一括登録するバッチは別途用意します(`_reftool/tools/` 予定)。
メモ1には書き込まず、メモ2に既存内容があるファイルはスキップします。
